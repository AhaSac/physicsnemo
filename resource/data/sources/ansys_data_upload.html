Data Upload

Learn about the input files and formats expected by the Ansys SimAI platform for model building and their processing.

To start building your AI models, you need to prepare what you are going to train your model with, that is your training data.

  • Supported Input Files and Formats
  • Data Processing
  • Data Allocation

Supported Input Files and Formats

Training data correspond to a folder containing your simulation data, that is:

  • one surface file [Required file] that represents the geometry and the target surface fields (2D data).

    If you have multiple surface files to represent one geometry, you must merge the parts before uploading.

  • and when relevant:

    • one volume file [Optional file] that encodes the volume fields (3D data).

      If you have multiple volume files to represent one geometry, you must merge the parts before uploading.

    • one scalar file [Optional file] that specifies the operating conditions (0D data) of the case to the AI model.

      This file allows you to define what is changing from one training data point to another (the inlet velocity or the fluid temperature for example). It enables you to provide extra information that is not tied to the design itself, yet still affects the simulation results. JSON is an open standard file format commonly used that can be edited using any text editor.

      Example of a scalar file:
      Note: Scalars have no units. Use values that are consistent with the training data.
      {
 "Mach": 26.72,
 "AoA": 0,
 "Farfield_Pressure": 0.076098624,
 "Farfield_Temperature": 192,
 "Wall_Temp": 485
}

Each simulation folder can contain those three types of input files, and they must be unique per simulation folder.

For more information about converting data into a supported format, see Data Conversion.

Data Processing

The raw data you upload to the platform are analyzed and preprocessed to be turned into universal, AI-ready data aligning with a canonical internal format. For more information on how to upload data, see Adding Data.

Any conversion failure at the upload stage raises an error mentioning that the training data cannot be used to build a model.

The four processing states (Uploading, Waiting for data extraction, Extracting data, Ready for model) are displayed and available in the product interface.

Data Allocation

To build an AI model, the data which you uploaded to the Ansys SimAI platform have to be distributed into two subsets: a training subset and a test subset. A randomized distribution ensures that a varied type of data points is selected and that the model remains unbiased.

The randomized data allocation is automatic, but if you desire to customize the allocation, a manual distribution is available through PyAnsys methods to assign your training data points into either the test or training subsets. This type of distribution might introduce unwanted bias and should be avoided except for the following cases where it can be particularly relevant:
  • Transient cases. They require timestamps to be kept together. That is why the data allocation must be done per design. This means the whole batch of training data of a transient case study, with all its timestamps, must be manually assigned to either the training subset or in the test subset.
  • Scarce geometries. If your test geometries are scarce, it is a good idea to force them into the test subset.
  • Automorphing cases. You will need to add optimized geometries generated by the non-parametric optimization feature to your project to retrain your model on them. For more information, see How to optimize the geometries using SimAI automorphing (PySimAI).
